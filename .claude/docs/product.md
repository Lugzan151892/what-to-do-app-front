# Продукт: что строим

**Weeknd** — приложение, которое помогает находить идеи, чем заняться в выходные.

## Ключевые сценарии
1. **История активностей.** Пользователь записывает, чем занимался: место/событие, дата, категория.
2. **Оценки.** Каждой активности ставится оценка (1–5 ★) и при желании заметка: что понравилось больше, что меньше. На основе оценок строится профиль предпочтений по категориям.
3. **AI-генерация идей.** По запросу пользователя. Перед генерацией задаются настройки:
   - **количество человек** (компания);
   - **только новое** — исключить то, что уже есть в истории;
   - **бюджет на человека** (есть в макете лендинга);
   - **город** пользователя.
   AI ищет актуальные события и места **на текущую дату** в городе пользователя (афиши, выставки, фестивали) с учётом истории и оценок и показывает результат карточками.

## Доменные понятия (глоссарий)
| Термин | Смысл | Где уже есть в коде (моки/вёрстка) |
|---|---|---|
| Активность (activity) | Запись в истории: название, дата, иконка/категория, оценка | `IOpportunityActivityItem`, `ActivityRow` |
| Оценка (rate) | 1–5, плюс опциональная заметка | `RateStars` |
| Категория | Активный отдых, культура, еда и рестораны, развлечения… | `ProgressBar` в «Умных оценках» |
| Профиль предпочтений | Насколько пользователю нравится каждая категория, в % | там же |
| Настройки генерации | Количество людей, только новое, бюджет, город | `SettingsSection`, `ButtonOptions`, `Stepper`, `WSwitchButton` |
| Идея / результат генерации | Карточка: название, место, когда, картинка, бейдж «Новинка/Топ» | `GeneratedCard`, `FloatingCards` |
| Город | Город пользователя, источник актуальных событий | блок «Москва · Данные обновлены сегодня» |

## Текущий статус
- **Сделано:** вёрстка лендинга `/` с моковыми данными. Его секции иллюстрируют будущие функции: «Как это работает» (3 шага), «Возможности», «AI-генератор».
- **Ещё нет:** авторизации (`/login` — заглушка), бэкенда и API, хранения данных, самих экранов приложения (история, добавление и оценка активности, генерация, профиль, выбор города), интеграции с AI.

## Ориентиры для будущих задач
- Компоненты лендинга — это прототипы экранов приложения. Когда будут делать реальные экраны, `ButtonOptions`, `Stepper`, `WSwitchButton`, `RateStars`, `GeneratedCard` нужно доработать до управляемых (`value`/`onChange`), а не верстать заново.
- Моковые интерфейсы (`IOpportunityActivityItem` и т.п.) — черновик доменной модели. При появлении API выносить типы сущностей в общее место, а не держать в файлах компонентов.
- Генерация зависит от текущей даты и города: город и дату нужно явно передавать в запрос, а результат считать недолговечным.
- Архитектурные решения (стейт, работа с данными, AI-провайдер) пока не приняты. Не выбирать их молча: предлагать пользователю.
